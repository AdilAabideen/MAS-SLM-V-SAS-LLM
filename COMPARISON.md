# Comparing a paired experiment

`mas_slm_research.comparison.compare_experiment(run, grader=...)` derives the report from the completed or cancelled `ExperimentRun`. The function checks that each recorded attempt appears exactly once in its case/repetition pair and that terminal and grade identities agree. The report keeps an outcome for every pair; a failed or unstarted arm has no comparable score rather than vanishing from the data.

Each system summary gives attempted count, valid completions, graded count, passes, execution failure kinds, grader errors, model and tool call counts, recovered text tool calls, malformed-call retry decisions present in the trace, usage-source counts, token totals, cost estimate, and the sum of measured workflow wall times. `task_score_all_attempts` divides known scores by all attempts, counting execution failures and unknown grader judgments as zero for a conservative lower bound. `task_score_graded_only` divides only completed and graded scores by its explicit `graded_only_denominator`. The optional grader hook produces a separate task-specific `grader_summary` from the same records. Pair wins, losses, and ties compare only two graded numeric scores; failed or missing arms count as uncomparable.

Token totals are `null` if any included model call lacks that token field. The report separately counts `provider`, `estimated`, and other usage sources so estimates cannot masquerade as provider measurements. A cost estimate requires an explicit `PriceRate` for every role that made a call; missing pricing or required token counts leaves cost `null`. `configured_prices(loaded)` reads prices only from model catalogs explicitly selected in configuration. It does not infer rates from a model name. Prices are research assumptions in USD per 1,000 tokens, not a provider bill.

`workflow_wall_seconds` sums each terminal `CaseResult.timing.wall_seconds` within a system. `child_seconds_sum` remains an attempt diagnostic: concurrent MAS children may overlap and their summed durations are not workflow elapsed time. Repair counts distinguish recovered text tool calls and recorded malformed-call retry decisions; they do not claim to include unrecorded retries. Reports use the underlying call/event traces and grade records rather than database counters.
